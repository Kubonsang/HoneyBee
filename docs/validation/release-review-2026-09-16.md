# 2026-09-16 릴리즈 검토

## 결론

공개 후보는 **0.1.0-beta.32**다. beta.31은 서비스 마이그레이션용 QA 기준
버전이고, beta.33/34는 연속 업데이트 검증용이다. 이를 공개 버전으로 혼동하지 않는다.
현재 공개된 GitHub 릴리즈는 beta.11이다. 이 검토에서는 게시하거나 태그를 만들지 않았다.

배포 파일과 Ed25519 서명 검사는 통과했다. 사용자 보고를 근거로 최종 후보에
연결한 인수 항목은 05/06/07/14다. 나머지 12개는 과거·로컬 증거가 있지만
최종 통합 범위까지 충족했다는 결론이 아직 없다. **12개를 전부 새로 테스트하라는
뜻은 아니다. 반대로 모두 서류 정리만 남았다는 뜻도 아니다.**

## 무엇을 얻었나

- 앱 파일을 버전별로 보관하고 안정적인 Launcher/CLI 경로를 유지한다.
- 정상 서비스 교체와 동일 버전 Setup Repair 후 원래 프로젝트를 유지했다.
- 강제 전원 차단 후 설치된 Launcher의 자동 롤백을 실제 VM에서 확인했다.
- beta.32 → 33 → 34 두 번의 업데이트가 연속 커밋됐고 서비스 영수증 바이트는
  변경되지 않았다. 프로젝트 ID, Workspace 연결, 브랜치 및 사용자 수정 보존을 확인했다.
- VHD 정보 조회와 분리 핸들의 권한·공유 충돌, 광학 볼륨 열거 오류, 압축 NTFS
  디렉터리 취급 등 실제 서비스 교체를 막는 문제를 찾아 수정했다.

검증은 실패 시 앱 실행 불능이나 작업 파일 손실을 발견하려는 것이었다. 그러나
검증 도구의 잘못된 가정, 지나치게 포괄적인 오류 메시지, 반복 빌드와 증거 관리
부족도 많은 재작업을 만들었다. 200GB 이상의 출력과 호스트 디스크 고갈은
일반 사용자에게 필요한 설치 용량이 아니라 개발·QA 산출물 누적이었다.
이 반복 전체를 제품 안전성에 필수였다고 설명하지 않는다.

## 게시 전 남은 결정과 작업

### 후속 소스/배포 준비

2026-09-16 소스 정리에서 Vitest가 node:test 파일까지 수집하던 오류를 수정했다.
Node 기반 QA 테스트를 `test:qualification-flow` 및 `test:run`에 연결했고,
누락된 combined-coordinator 테스트도 포함했다. QA 스크립트의 전역 참조와
포맷도 정리했다. 검증한 beta.32 바이너리는 교체하지 않았다.

lint, typecheck, build, 전체 `test:run`, deps:check가 통과했다. 보안/라이선스
검사도 통과했다. `pnpm verify` 최초 실행은 포맷 단계에서 중단됐으며, 작업 관련
포맷은 수정했다. 별도 사용자 분석 메모 두 개는 수정하지 않았으므로 aggregate
`verify` 전체 통과라고 주장하지 않는다. 실제 커밋 대상 포맷은 별도로 확인한다.

WinGet 매니페스트 validate는 종료 코드 0으로 통과했다. Git.Git 의존성 자체는
그 명령이 검증하지 않았으며, 로컬 설치 결과를 대신하지 않는다.

배포 스크립트의 초안 업로드와 공개 승인을 분리했다. `stage`는 파일 검증 후
비공개 초안 업로드/재다운로드 검사를 할 수 있다. `publish`의 전체 인수 조건은
유지된다. 새 정책 테스트 7개가 통과했으며, 초안 생성만으로 공개 완료로 기록하지 않는다.

1. 전체 고정 계약을 유지하면 위 공백을 기존 증거/변경 영향으로 닫고 실제 미검증
   부분만 실행해야 한다. 지금 전체 통과로 기록하거나 게시 스크립트를 우회하지 않는다.
2. 사용자가 제한된 실험판으로 공개 범위를 바꾸면, 미검증 항목을 그대로 공개하고
   승인된 예외를 별도 릴리즈 정책에 기록해야 한다. 기존 게이트를 통과로 바꾸지 않는다.
3. 어느 경우든 배포 소스 커밋, 후보 바이트와의 연결, 정확한 릴리즈 노트를 확정하고
   업로드한 파일 해시를 확인한 뒤 공개한다. 배포를 위해 또 거대한 후보 빌드를
   무조건 생성하지 않는다.
