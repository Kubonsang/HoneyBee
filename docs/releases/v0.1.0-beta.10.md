# HoneyBee 0.1.0 Beta 10 — Smaller Bee caches

This Windows 11 x64 prerelease applies native NTFS compression to the independent
Bee cache of newly created Workspaces. It packages storage component
**0.0.0+cfa606fd4143.hb12**.

## Changes and measured results

- Compress the private Bee data after seeding and before granting Unity write
  access. New files inherit compression. Reattachment preserves modified caches.
- Reuse existing external-Bee parent seeds. Existing Workspaces, immutable parents
  and VHDX containers are not recompressed or migrated.
- In the paired GNF study, combined child plus Bee allocation fell from
  **483.80 MB to 392.31 MB (18.91%)**. Private Bee fell from 155.56 MB to 63.04 MB;
  child allocation remained approximately 329 MB.
- First-open time changed by +0.54%, ready time by +1.92%, reopen by -4.51%,
  edit/test by +9.01% and PlayMode by +2.69%. These results describe one project
  and host, not a guarantee for other workloads.

The original 20% reduction gate remains missed. The practical reduction was
accepted with every measured timing regression within 10%. Authored/Git files,
shared parents and other caches are additional costs; a 300 MB total Workspace
is not guaranteed. The separate product lifecycle workload observed approximately
423 MB per child plus private Bee before detach.

## Download and upgrade

1. Download `HoneyBee-win32-x64.zip` for Desktop or
   `HoneyBee-cli-win32-x64.zip` for CLI, verify `SHA256SUMS.txt`, and extract the
   complete archive into a new directory. CLI requires Node.js 24 or newer.
2. Extracting the ZIP does not upgrade the Windows service. Follow the included
   `STORAGE-SETUP.md` (Desktop) or `README.md` (CLI) for the qualified **hb11 to hb12**
   upgrade, preserving the existing root and user SID. An already matching hb12
   installation does not need another replacement.
3. Re-register existing projects using the new CLI's `project init` and the same
   source/Workspace-root paths to update tool paths. Use **Repair** where required
   and check Doctor before use.
4. Create new Workspaces to obtain compressed private Bee caches. Existing
   external-Bee parent seeds can be reused directly. Legacy parents need a new
   `cache prepare` with the source Unity Editor closed. Existing Workspaces do not
   shrink automatically.

## Validation and limits

- Product broker integration passed **572 Unity tests** in 22 TestPlay runs,
  including concurrent retained cycles and removal/survivor checks.
- Native tests checked compression inheritance, uncompressed retained-cache
  compatibility, busy-file refusal, removal abort and interrupted-removal recovery.
- Installed hb11-to-hb12 checks, SCM restart and one physical Windows reboot
  passed. Legacy and compressed fixtures reattached with their contents intact;
  all disposable installed child Workspaces were then removed.
- An initial installer interruption left the new executable beside an old receipt.
  The existing installer reconciliation completed recovery. Two original user
  disk hashes had changed at that interruption; their exact byte changes were
  not determined. File identities and journals were unchanged, and preservation
  checks passed from a separately recorded recovery baseline through reboot and
  cleanup. The validation record retains this limitation.
- Fresh installation, older service migrations and repeated physical reboot
  campaigns remain outside this release's qualification. Windows archives are
  unsigned.

See the tagged source's `docs/validation/workspace-footprint.md` and
`docs/validation/bee-compression-product.md` for samples, evidence and cleanup scope.
