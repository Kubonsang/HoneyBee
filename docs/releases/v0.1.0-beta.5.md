# HoneyBee 0.1.0 Beta 5 — existing-install evaluation

This prerelease is for Windows 11 x64 users with a working HoneyBee installation and the matching
`0.0.0+68e05e0bf0e4.hb8` storage service. Fresh Windows installation and migration from Beta 3 have
not been validated for this release. Keep the existing matching service; do not replace or downgrade
it while it owns Workspaces.

## Changes

- Correct changed-file selection and diffs for Unicode, spaces, quoted paths and renames.
- Bound streamed diffs to 1 MiB and ignore stale responses after navigation.
- Show Korean/English setup guidance with storage version and hash diagnostics.
- Include Desktop setup documentation and verify CLI, Desktop IPC/UI and packaged PTY in Windows CI.

## Download and use

Download `HoneyBee-cli-win32-x64.zip` for the CLI or `HoneyBee-win32-x64.zip` for Desktop. Verify
the ZIP against `SHA256SUMS.txt`, then extract the entire archive into a new directory. Keep the
previous application directory until evaluation is complete. Read the included setup documentation
and run Doctor before creating a Workspace. Use a disposable project for initial evaluation.

After Windows restarts, a retained Workspace requires explicit **Repair** before Unity or other
tools use it. If removal reports `workspace.in-use`, let the relevant tools finish, close them and
retry normal removal. HoneyBee preserves the Workspace and never forces those processes to exit.

## Validation and limits

The packaged application source passed 63 TypeScript tests, Go host tests and all seven checks on
[PR #39](https://github.com/Kubonsang/HoneyBee/pull/39). The
[Windows quality run](https://github.com/Kubonsang/HoneyBee/actions/runs/33955043050) verified CLI,
Desktop IPC/UI and packaged PTY. These ZIPs are the original tested CI archives; they were not rebuilt
after the physical Windows test.

The CLI candidate passed four linked-worktree checks on a disposable real Unity project with
Unity 6000.3.8f1, paired batch Editor executions, isolated authored commits, junction repair,
dirty/open-handle refusal, repeated removal and branch preservation. An actual Windows reboot was
followed by repair of the same retained storage, authored and Library hash checks, Unity execution
and normal removal. Final Doctor passed 19 checks with no warnings or failures. The original
Workspace and registry were preserved and all six disposable test Workspaces were removed.

This is existing-install evidence on a shared host. Fresh installation, Beta 3 service upgrade,
zero-baseline storage benchmarking, interactive GUI Editor sessions and external Codex/Claude runs
were not verified by this follow-up procedure. Desktop has automated IPC/UI and PTY coverage;
the physical reboot lifecycle was exercised through the CLI. The Windows bundles are unsigned.
