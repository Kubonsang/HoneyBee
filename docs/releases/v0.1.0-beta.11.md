# HoneyBee 0.1.0 Beta 11 — Choose your starting commit

This Windows 11 x64 prerelease lets you choose a Workspace's starting point without typing a
commit hash. It retains Beta 10's storage component **0.0.0+cfa606fd4143.hb12**.

## Changes

- Select a local branch, tag, or locally available remote branch, then choose a commit by its
  message, author, and date. Browse older commits in pages of 50.
- Default to the source project's current commit and pin the selected commit when displayed.
  Later branch movement does not change the Workspace's starting point.
- Keep manual branch/tag/SHA entry under Advanced and preserve CLI `--base` behavior.
- Retry failed lookups, ignore stale responses, and prevent creation from an unresolved selection.
  Korean and English interfaces are included.
- Reuse shared Git objects and the existing Library parent. Selection does not fetch, clone,
  create a permanent history index, or rebuild the cache.

## Measured overhead

In a local 101-commit fixture, references plus first-history-page retrieval measured **191 ms p95**.
Across 10 alternating pairs, median create time changed from **3,190.74 ms to 3,195.61 ms**
(**+4.88 ms / +0.15%**). Query file snapshots were unchanged and storage call counts were identical.

These measurements use a directory-backed storage adapter and cover Core/Git overhead, not
Electron rendering, physical VHDX allocation, large-project checkout, or Unity import time.
See `docs/validation/workspace-base-selection.md` in the tagged source for raw evidence and limits.

## Download and upgrade

Source validation passed 95 Vitest cases and Go storage tests. Packaged CLI, Desktop IPC/UI,
and interactive PTY smoke tests passed; package validation verified the existing hb12 payload hashes.

1. Download `HoneyBee-win32-x64.zip` for Desktop or `HoneyBee-cli-win32-x64.zip` for CLI, verify
   `SHA256SUMS.txt`, and extract the complete archive into a new directory. CLI requires Node.js 24+.
2. An existing hb12 storage installation needs no replacement. Extracting a ZIP does not install
   or upgrade the service. For hb11 installations, follow the included `STORAGE-SETUP.md` (Desktop)
   or `README.md` (CLI) and preserve the existing root and user SID.
3. Re-register existing projects with the new CLI's `project init` and the same source and
   Workspace-root paths to update bundled tool paths. Check Doctor and use Repair when needed.

Existing Workspaces and Library parents keep their storage layout. Beta 10's qualification for
hb11-to-hb12 upgrades is retained; fresh installation, older migrations, and additional physical
reboot campaigns are not newly qualified by this release. Archives are unsigned.
